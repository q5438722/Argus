# 统一规格产物目录

对应[英文 Skill](../spec-artifact-workspace.md)。

所有生成产物使用操作者指定的、位于 home 下的同一个根目录。
当前 Rust std 任务采用：

```text
~/rust-std-specgen-artifacts/
    runs/<campaign-directory>/
    toolchains/<baseline-date>/
```

spec、两类 proof、查询、issues、项目日志和临时构建均放在对应 campaign 目录内。
固定工具链放在 `toolchains/` 下只读共享，不按 proof attempt 复制。
不得再直接在 `~` 下创建新的任务产物目录。
搬迁已有任务时，可保留原目录 basename，避免改变按名称定位的项目缓存或知识路径。

Manager 将准确的绝对路径交给所有角色；新文件从该 workdir 使用相对路径组织，
不另起第二个产物根。外部源码仓库和既有 Argus 控制 profile 不因此自动搬迁；
新 profile 在受支持的生命周期配置允许时，也可放进统一根目录。

## 搬迁现有任务

迁移正在运行的工作须获操作者批准。先保存工作、记录未完成命令和恢复点，
再用受支持的协作停止/drain 控制暂停任务，之后才搬迁工作目录或正在使用的共享依赖。
不强杀无关进程，不手改任务控制文件冒充已停止；恢复时使用原 project ID。

事先核对并列出准确的源/目标目录，目标冲突时拒绝覆盖。
同文件系统优先直接 rename，避免复制大规模 proof 树。
保留隐藏文件、权限、硬链接及全部唯一源码/proof/query；
不能把递归删除大目录作为搬迁的一部分。

历史证据常含绝对路径。获准时用明确的兼容符号链接保留旧路径，并记录映射。
真实产物目录位于统一根下，旧链接不是新产物位置。
不能只为换路径改写历史命令、查询、快照、hash 或证明裁定。

通过受支持的 workdir/configuration 接口更新任务元数据，
将启动配置和后续目标改为新规范路径；
独立核对兼容链接、保护文件 hash、原任务 ID 和恢复状态。
只有确认历史依赖已不需要旧路径并具备清理授权时，才能删除兼容链接。

## 保持存储和隔离限制

统一目录不解除原有输入投影/空闲空间保护。
完整性快照排除其他任务、旧 runs、工具链、下载内容及 proof-only 适配 sysroot，
但不能裁掉真实依赖。各并行任务使用独立输出位置，
Reviewer 仍按只读输入和单独可写 scratch 执行。
父目录搬迁不扩大对受限历史资料的访问权限。
