# 让规格接入既有抽象

对应[英文参考](spec-abstraction-integration.md)。

当 API 创建或暴露的值需要通过既有库协议消费时，使用本参考，
尤其适用于 iterator 和借用 view。
本文补充[共享 Verus 工作流程](../verus-spec-generation-and-repair.md)，
是参考知识，不是独立 Skill，也不授权修改源码、verifier 或可信基础。

## 1. 先复用语义协议，而不是另建平行 view

检查目标库基线已有的规格协议：trait extension、状态观察、
consumer 合同、启用条件及附近的实现。
只复用类型或命名风格不够；新增 API 的保证必须能传递到调用者实际使用的合同。

优先实现或扩展该协议，不要默认增加一套含相似字段的独立 view。
若现有抽象不足，说明缺少的观察量，并提供新模型与既有接口之间的源码对应桥接。
不要求 Manager 选择具体表示，也不因 API 是新增的就强制新增 view。

## 2. 建模 consumer 实际拿到的值

根据源码和 docstrings 选择可观察内容、顺序、返回分支、状态变化及借用效果。
源内容、长度、方向、分组大小等元数据可以支撑模型，
但它们本身并没有确定实际返回值。

Iterator 的标准剩余序列是 `Seq<Self::Item>`，
不一定是展平的源元素序列。若每次返回一个 slice，
就描述 slice 序列及各自的内容、顺序与边界，保留真实 item 类型和泛型调用域。
完整性结果明确区分 view-level 唯一性与原始返回值身份，不能混为一谈。

## 3. 接通构造、消费和后续观察

检查 constructor -> consumer -> observer 链，而不只检查创建时的元数据。
构造建立所选协议状态及适用的启用条件；
消费通过已有合同给出返回值和状态转换；
后续 observer 与实际观察的当前状态一致，包括适用的耗尽行为。

辅助 observer 在构造时等于协议状态，只是 constructor-only 关系，
除非另行建立保持性或相对当前状态的关系。
没有该依据就不能在消费后继续使用初始等式。
同样，声明 trait conformance 本身不证明源码实现满足所声称的规律。

优先复用既有协议的转换和终止支持，而不是再写一套状态机。
若协议无法表达必要行为，保留具体缺失义务，
不能把孤立的 view 当作完整 API family。

## 4. 保留借用与回调效果

可变借用 item 同时描述初始内容、最终值如何写回 owner，以及未影响区域的 frame。
适当使用目标基线已有的 `old`/`final` 和 prophecy 支持。
不能机械复制不可变版本、冻结调用者的合法写入，
也不能把借用最终值误认为一定执行了析构。

回调驱动的 consumer 保留相关回调前提、状态、调用行为和终止条件。
一个未接通的纯 predicate，不会因参数相同就成为有状态回调的模型。

## 5. 按语义连接判断辅助模型

Ghost 或 uninterpreted helper 不因语法本身而一律禁止。
它必须有有意义、基于源码的约束，并连接选定观察量与 consumer 合同。
在支持条件内复用既有可信抽象；不新增公理、不假设目标答案，
也不能用 opaque helper 隐藏缺失行为。

这不放宽任务明确提出的 zero-UF 等要求。
区分这种额外要求与库的接入 style，剩余边界或 blocker 要明确披露，
不能包装成已完成。

## 6. 通过真实客户端使用合同

把代表性的验证客户端加入仓库已有测试套件。
调用真实 API，加载实际候选合同，不手动假设预期输出。
对有状态 family，覆盖有意义的构造和消费过程、
适用的边界/耗尽情况，以及有关的可变借用写回。

断言能区分预期行为与元数据-only、未约束模型的具体观察量。
只检查创建、长度或 well-formedness，可能完全没有触及缺失的语义连接。
范围限于受影响行为，不穷举所有组合，也不新增测试框架。

这些客户端检查接入与可用性，不能替代任一必要证明链。
源码 correctness 仍证明实现对应，completeness 仍使用明确的观察量和比较关系。
孤立模型里答案唯一，不证明库的 consumer 已与它接通。

## 来源示例，不是固定模板

[verus-lang/verus#2839 的 review](https://github.com/verus-lang/verus/pull/2839#pullrequestreview-5432144255)
要求复用既有 iterator 规格接口，而不是独立 view。
[verus-lang/verus#2836 的改动](https://github.com/verus-lang/verus/pull/2836/files)
展示了构造合同与该接口的连接，以及普通迭代客户端。
应推广这种连接，不固化某个 API 的 helper 名称、公式或表示。
当前路径、版本和范围留在项目里。
