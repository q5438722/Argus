# 仅用于 Verus 正确性证明的字段可见性放宽

对应[英文 Skill](../verus-proof-only-field-visibility.md)；
同时遵循[共享规格流程](verus-spec-generation-and-repair.zh-CN.md)。

规则：**proof-only-field-visibility-v1**，2026-10-13 获得操作者授权。
这是正确性证明的源码适配规则，不是公理、新的语义信任边界，也不免除源码正确性。

## 当且仅当用于正确性证明

只有在证明实现满足 spec 时，才允许在**隔离的正确性证明源码副本**中，
把 private 或受限可见性的字段改成 `pub`。必要时可放宽该副本中的全部此类字段，
默认只改需要访问的部分，不对整个仓库无差别替换。
范围包括 Rust 允许修改可见性的命名字段、tuple 字段，以及默认私有、
`pub(crate)`、`pub(super)`、`pub(in ...)`。

不修改真实 Rust/std 源码、已安装或共享 sysroot、官方 Verus/vstd 基线及正式库。
适配源码和需要重建的证明专用库/sysroot 放在独立正确性证明目录，
例如 `proofs/correctness/<family>/visibility/`。
该构建不能替换正式 spec、接入客户端或 completeness 使用的原库。
大体积适配构建不得进入 specdet 输入快照，原存储保护继续生效。

例如，仅在这个副本中允许：

```diff
-    pub(super) iter: slice::Iter<'a, T>,
+    pub iter: slice::Iter<'a, T>,
```

授权仅限字段可见性。字段名、类型、顺序、布局属性、泛型、bounds、生命周期、
初始化、方法体、分派和 Drop 行为都保持不变；不能增删字段，也不能顺便公开
方法、类型或模块。其他源码转换仍走原有的单独授权和严格对应性审阅流程。
普通 ghost 注解和 lemma 与可见性差异分别记录。

## 临时公开的字段不能泄漏到正式 spec

正确性证明的函数体、内部不变量及源码到 view 的 lemma 可以访问这些字段；
**导出的 API 合同不能依赖它们**。合同仍使用原公共接口及有源码依据的抽象，
例如 `@`、`IteratorSpec::remaining`、返回变体及适用的 old/final 内容关系。
不能通过导出的辅助谓词把对临时字段可见性的依赖藏起来。

原 API 本来就公开的字段仍可正常使用；这里禁止的是依赖“仅为证明才公开”的字段。

例如 `Drain::as_slice` 的公开保证仍是：

```rust
ensures
    returned@ == IteratorSpec::remaining(drain),
```

不能因为证明构建现在能访问 `drain.iter`，就把该字段写入公开合同。
两个迭代器当前内容的联系可在内部源码/view 证明中建立，
但放宽可见性本身不提供这条联系。

本 Rust std 规格任务不要求指针或 ownership 属性的 spec/completeness。
正确性证明内部可在需要时使用相关机制来建立所需的值/内容结论，
但不能把它们变成额外的公开后置或 completeness 验收门槛。
回调及其他操作对最终元素内容的影响不因此被排除。

## 可见性不等于类型对应或不变量

只修改 verifier 没有编译的文件，不能解决访问权限。
必须记录正确性构建如何实际使用适配后的声明，而不是仍导入原预编译 std 类型。

字段同名的本地结构体不自动等于 `std::vec::Drain`。
若采用本地镜像或重建的证明专用 crate，改变了类型身份或编译上下文，
须保留明确的原始/证明类型与方法映射，并独立核查相关表示、调用及 view 对应。
不能直接假定布局相同、trait 分派可互换，或把镜像的证明当作原 API 的证明。

公开字段可能允许原调用者不能做的构造和写入。证明须保留原可达状态域。
值/内容证明需要的表示不变量，应来自已有构造器/合同或已证明的对应，
不能发明新的 API 前提，不能因字段原来私有就假定它有效，
也不能拿目标后置式作不变量假设。

本授权不会解除 Verus 的 opaque 类型、移除 `external_body` 或补出缺失 callee 合同；
不授权 `assume`、`admit`、新公理、编译器隐私绕过或 checker 修改。
遇到其他限制时精确记录，不扩张授权，也不把跳过原体算成证明。

## 证据与独立审阅

在已有逐 API 源码对应记录中保留：

- 固定原始来源、原始/适配路径与 hash，以及精确字段可见性 diff。
  其他 ghost/外壳改动分别识别，并审读声明和方法体上下文，拒绝混入别的修改。
- 原类型/方法到证明对象的映射、所需的有效状态/view 不变量、
  实际构建命令及被编译的源码/库路径。
- 对未改变的公开合同检查相关方法体的正确性结果，
  以及独立的对应性与证明审阅。
- 用原始未改库检查正式 spec 和接入客户端，completeness 同样只针对该公开合同
  和选定观察；输入中不得带入适配声明、证明专用 crate 产物或临时公开字段访问。

字段可见性这一种适配已获授权，不必只为尝试它再次等待 implementation-change 批准。
但记录适配、独立审阅后才能计入结果的要求不变；越出字段可见性的修改另行授权。

若公开合同与 completeness 输入均未改变，可复用仍匹配的既有完整性证据，
不因可见性授权重跑或改变其裁定。保留旧 private 失败，
新源码结果标明采用已记录的 proof-only 适配；不自动把旧阻塞项升级为通过。
